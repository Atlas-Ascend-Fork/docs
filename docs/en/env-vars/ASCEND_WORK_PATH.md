# ASCEND_WORK_PATH

## Function Description

If developers want files generated during compilation and running to be stored in a unified path, they can use this environment variable to set the storage path for **node-exclusive files**. The node-exclusive files generated by each component during compilation and running will be stored in the path defined by this environment variable.

- The path can contain uppercase and lowercase letters (a-z, A-Z), digits (0-9), underscores (_), hyphens (-), periods (.), and Chinese characters.
- If the specified path exists and is valid, ensure that the executing user has read, write, and execute permissions. If the specified path does not exist, the software automatically creates it.

**Files under ${ASCEND_WORK_PATH} include:**

- **`${ASCEND_WORK_PATH}/aoe_data/`**: Records information related to the AOE tuning process, including the tuning task name, tuning duration, model execution time/operator execution time before and after tuning, and knowledge base hit information.

  Priority description:

  **ASCEND_WORK_PATH** > AOE default tuning working directory
  
  The AOE default tuning working directory is the value of the **WORK_PATH** parameter in **\${install_path}/latest/tools/aoe/conf/aoe.ini**.

  <!-- npu="950,A3,910b,910,310p,310b" id2 -->
- **`${ASCEND_WORK_PATH}/log/`**: log files.

  Priority description:

  **ASCEND_PROCESS_LOG_PATH** > **ASCEND_WORK_PATH** > Default log storage path (**$HOME/ascend/log**)
  <!-- end id2 -->

- **`${ASCEND_WORK_PATH}/atrace/`**: trace log files.

  Priority description:

  **ASCEND_WORK_PATH** > Default trace log storage path (**\$HOME/ascend/atrace**)

- **`${ASCEND_WORK_PATH}/profiling_data/`**: storage path for the performance data collected by the Profiling tool.

  Priority description:

  Offline inference scenario:
  
  - If performance data is collected through the `msprof` command, the priority is as follows:

    `--output` parameter > **ASCEND_WORK_PATH** > Default path (storage path of the model file used for inference)
  - If performance data is collected through the `acl.json` configuration file, the priority is as follows:

    Parameter **output** > **ASCEND_WORK_PATH** > Default path (directory where the application project executable file is located)
  
  <!-- npu="950,A3,910b,910,310p" id3 -->
  TensorFlow training/online inference scenario:
  
  The **output** parameter in the **PROFILING_OPTIONS** environment variable, the **output** parameter in the **profiling_options** configuration of the training script, and the **output_path** parameter configured by the training script when calling the **Profiler** class have higher priority than **ASCEND_WORK_PATH**.
  
  Note: In the training/online inference scenario, either the **output**/**output_path** parameter or the **ASCEND_WORK_PATH** environment variable must be configured; otherwise, the profiling performance data collection function reports an error.
  <!-- end id3 -->
  
  <!-- npu="A3,910b,910" id4 -->
  PyTorch training/online inference scenario:
  
  Performance data path specified by the **on_trace_ready=tensorboard_trace_handler** function > **ASCEND_WORK_PATH** > Default path
  
  If the **tensorboard_trace_handler** function is configured but no specific path is specified, the path can be set through the **ASCEND_WORK_PATH** environment variable. In this case, the performance data written to disk is automatically parsed. If the **on_trace_ready=torch_npu.profiler.tensorboard_trace_handler** function is not used in the code, the performance data set and written to disk through the **ASCEND_WORK_PATH** environment variable is raw data.
  <!-- end id4 -->

- **`${ASCEND_WORK_PATH}/kernel_meta/`**: Debugging-related process files generated during operator compilation, including but not limited to .o (operator binary files), .json (operator description files), and .cce files of the operator.

  The following scenarios provide parameters or APIs for setting the storage path of debugging process files generated during operator compilation, which have higher priority than the **ASCEND_WORK_PATH** environment variable. The details are as follows:
  
  - Scenario of offline model compilation using the ATC tool
  
    Parameter **--debug_dir** > **ASCEND_WORK_PATH** > Default path (**./*Current execution path***)
  
  - Scenario of building or compiling a model using AscendCL APIs
  
    - Parameter **DEBUG_DIR** in the graph building API **aclgrphBuildInitialize** > **ASCEND_WORK_PATH** > Default path (**./*Current execution path***)

    - Parameter **DEBUG_DIR** in the graph building API **aclgrphBuildModel** > **ASCEND_WORK_PATH** > Default path (**./*Current execution path***)

    - Parameter **ACL_DEBUG_DIR** in the application compilation API **aclCompileOpt** > **ASCEND_WORK_PATH** > Default path (**./*Current execution path***)

    <!-- npu="950,A3,910b,910,310p" id5 -->
  - Scenario of TensorFlow network training or online inference
  
    TF Adapter configuration parameter **debug_dir** > **ASCEND_WORK_PATH** > Default path (**./*Current execution path***).
    <!-- end id5 -->

- **`${ASCEND_WORK_PATH}/${pid}_${device_id}`**: In the scenario where DUMP graph description printing is enabled (that is, the scenario where the **DUMP_GE_GRAPH** environment variable is configured), the corresponding DUMP graph files are written to the disk.

  Priority description:
  
  Environment variable **DUMP_GRAPH_PATH** > **ASCEND_WORK_PATH** > Default path (**./*Current execution path***)

- **`${ASCEND_WORK_PATH}/extra-info/data-dump/`**: exception dump files and abnormal operator compilation information.
  
  Priority description:

  Environment variable **NPU_COLLECT_PATH** > **ASCEND_WORK_PATH** > Default storage path (current execution path).

- **`${ASCEND_WORK_PATH}/tmp_weight_${pid}_${session_id}`**: In the scenario where external weights are enabled, this directory stores the weight files of Const and Constant nodes.

  The method for enabling external weights varies by scenario. For details, see the user guide or development guide of the corresponding scenario.
  
  Priority description:

   **ASCEND_WORK_PATH** > Default path (**./*Current execution path***)

- **`${ASCEND_WORK_PATH}/FE/${pid}/fusion_result.json`**: fusion rules that are still in use after excluding the fusion rules disabled in the **fusion_switch.cfg** file.

  Priority description:

  **ASCEND_WORK_PATH** > Default path (**./*Current execution path***)

- **`${ASCEND_WORK_PATH}/check_result.json`**: model precheck result file.

  When using the ATC tool for offline model compilation, if **--mode=0** is set in the **atc** command and model parsing fails, or if **--mode=3** is set to perform only model precheck, this environment variable can be used to specify the path for saving the precheck result file.

  Priority description:

  Parameter **--check_report** > **ASCEND_WORK_PATH** > Default path (**./*Current execution path***)

- **`${ASCEND_WORK_PATH}/printf/`**: data files dumped from operator kernel data.

  Priority description:

  **ASCEND_DUMP_PATH** > **ASCEND_WORK_PATH** > Default path (current execution path).

## Configuration Example

```bash
export ASCEND_WORK_PATH=/repo/task001/172.16.1.12_01_03
```

The configured path must be an existing directory, and the execution user must have read, write, and execute permissions on it. The last field of the path must uniquely identify the current machine.

It is recommended that this unique identifier be composed of **machineID**, **vmID**, and **dockerID**, for example, **machineID_vmID_dockerID**.

- **machineID**: IP address of the current machine.
- **vmID**: VM ID.
- **dockerID**: docker container ID.

In a physical machine environment, identifying by the IP address alone is sufficient.

## Constraints

In a multi-server scenario, the AI processor model, firmware driver, and CANN software version on each machine must be consistent.

## Supported Models

Supported on all chips
