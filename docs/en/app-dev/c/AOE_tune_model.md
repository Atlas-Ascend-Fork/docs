# Tuning Models with the AOE Tool

<!-- md-trans-meta sourceCommit=fdf4276c76935b494f8459e5a6e0a3e968866a42 translatedAt=2026-10-23T10:26:46.457Z pushedAt=2026-10-26T03:10:39.413Z nl=2 -->

This section describes the basic methods of using the **aoe command** for subgraph tuning and operator tuning in the **inference** scenario. **Before tuning**, see [AOE Tuning Tool](https://www.hiascend.com/document/detail/en/CANNCommunityEdition/latest/devaids/aoe/auxiliarydevtool_aoe_0001.html) to prepare the environment, understand the usage constraints, and learn the basic parameter usage.

When you use the **aoe** command for tuning, the following files are generated: an OM model file adapted to the AI processor, a tuning knowledge repository based on the AI processor, and a tuning effect file (through which you can view the performance improvement rate of each operator in the model). Because an OM model file is generated, the **aoe** command includes the model conversion function. Therefore, the parameters of the **aoe** command are generally based on the parameters of the **atc** command with the **--job\_type** parameter added to enable **subgraph tuning** and **operator tuning**. **It is generally recommended to perform subgraph tuning first and then operator tuning.** The reason is that subgraph tuning generates the graph segmentation method first. After subgraph tuning, the operators have been segmented into their final shapes. Then, operator tuning is performed based on these final shapes. If operator tuning is performed first, the operator shapes being tuned are not the final segmented operator shapes, which may affect the final tuning effect.

## Procedure

<a id="li621122115138"></a>

1. **Use the aoe command to perform subgraph tuning and then operator tuning.**
    - **The following is an example of the subgraph tuning command:**

        ```bash
        aoe --model=${HOME}/module/resnet50_pytorch_1.4.onnx --framework=5 --job_type=1
        ```

    - **The following is an example of the operator tuning command:**

        ```bash
        aoe --model=${HOME}/module/resnet50_pytorch_1.4.onnx --framework=5 --job_type=2
        ```

2. **View the tuning result.**

    The following tuning result indicates that tuning is complete and performance is improved. After tuning, a custom repository, an OM model file, and a tuning effect file are generated.

    ```bash
    <xxxx> process finished. Performance improved by xx%    //xxxx: tuning task name, xx%: performance improvement ratio.
    ```

    **The tuning result files are as follows:**

    - **Tuning knowledge repository based on the AI processor**
        - For subgraph tuning, the results are stored in the **$\{HOME\}/Ascend/latest/data/aoe/custom/graph/$\{soc\_version\}** directory by default.
        - For operator tuning, the results are stored in the **$\{HOME\}/Ascend/latest/data/aoe/custom/op/$\{soc\_version\}** path by default.

    - **OM model file adapted to the AI processor**

        The tuned OM model is stored in the current directory where the **aoe** command is executed by default. The specific path is as follows: **$\{model\_name\}\_$\{timestamp\}/tunespace/result/$\{model\_name\}\_$\{timestamp\}\_tune.om** (or **$\{model\_name\}\_$\{timestamp\}\_tune_\__$\{os\}\_$\{arch\}.om**).

    - **Tuning effect file**

        A file named **aoe\_result\_opat\_\{timestamp\}\_\{pid_xxx_\}.json** is generated in the current directory where the **aoe** command is executed, recording the information of the operators tuned during the tuning process.

        The following is an example of a content snippet in the JSON file:

        ```json
        {
                  "op_name": "Conv_125",
                  "op_type": "Conv2D",
                  "tune_performance": {
                    "Schedule": {
                      "performance_after_tune(us)": 72.046,
                      "performance_before_tune(us)": 72.055,
                      "performance_improvement": "0.01%",
                      "update_mode": "add"
                    }
                  }
        }
        ```

3. **Specify the tuning knowledge repository, and then perform model inference.**
    1. Set the **TUNE\_BANK\_PATH** environment variable to the path where the custom knowledge repository generated by AOE tuning is stored. The **graph** directory under this path stores the subgraph tuning repository, and the **op** directory stores the operator tuning repository. The following is an example:

        ```bash
        export TUNE_BANK_PATH=/home/HwHiAiUser/custom
        ```

    2. Perform model inference.

        Use the OM model file generated by the operator tuning command in [1](#li621122115138) to perform model inference.

        >**Note:** 
        >**The "one AOE tuning + multiple ATC model conversion" scenario is supported.** After the model is tuned using the AOE tool, if the model needs to be converted again due to other service requirements, you can specify the path of the AOE tuning knowledge repository through an environment variable and then use the ATC tool to convert the model again. In this way, the model can be compiled based on the tuning strategies in the repository, and a tuned model can be converted.
