# Operator Tuning

1. Dump operator information.

    Before operator tuning, you need to obtain the operator information statistics file (\*.json) of the model, including the shape, dtype, and format of operators. Currently, two methods are supported for dumping the operator JSON file. Select an appropriate method based on the actual situation.

    - **When programming with PyTorch Python APIs**, you can dump the operator JSON file through the Ascend PyTorch Profiler APIs. For details, see "Other Profiling Methods \> Ascend PyTorch Profiler" in [Performance Tuning Tool](https://hiascend.com/document/redirect/CannCommunityToolProfiling).

        1. Before training, enable the operator information statistics function in the extended parameter **experimental\_config**, that is, set the **record\_op\_args** parameter to **True**.

        2. View the collected PyTorch training performance data result file.

            After training, the dumped operator information statistics files are stored in the **\{worker\_name\}\_\{timestamp\}\_ascend\_pt\_op\_args/\{pid\}** directory by default.

    - **When using the ACL APIs**, you can dump the operator information statistics files to a specified directory through the **aclopStartDumpArgs** and **aclopStopDumpArgs** APIs. For details, see "Dump Configuration" in [Runtime API](https://hiascend.com/document/redirect/CannCommunityRuntimeApi).

2. Compile the static kernel package.

    In any directory, run the following static compilation command as the running user (for example, **HwHiAiUser**):

    ```bash
    op_compiler --op_params_dir=<dump_dir>  --soc_version=<soc_version> --log=info --job=8 --output=<output_dir>
    ```

    The key parameters are described as follows. For details about all parameters, see the "Command-Line Options" section in [Operator Compilation Tool](https://hiascend.com/document/redirect/CannCommunityopcompiler). Set the parameters based on the actual situation.

    - **--op\_params\_dir**: abbreviated as **-p**, required. This parameter specifies the path of the folder where the statistics data exported by the dump tool is stored. Both absolute and relative paths are supported.
    - **--soc\_version**: abbreviated as **-v**, required when compiling operators. This parameter specifies the AI processor model used for operator compilation.

        > **Note:** If you cannot determine the **soc\_version** of the current device, run the **npu-smi info** command on the server where the NPU driver package is installed to query it. Add **Ascend** before the queried **Name** value. For example, if the **Name** value is **_xxxyy_**, the actual **soc\_version** value to configure is **Ascend_xxxyy_**.

    - **--log**: abbreviated as **-l**, optional. This parameter sets the log level during operator compilation. The value can be **debug**, **info**, **warning**, **error**, or **null**, and the default value is **null**.
    - **--job**: abbreviated as **-j**, optional. This parameter sets the number of worker processes during compilation. The minimum value is **1**, and the default value is **16**.
    - **--output**: abbreviated as **-o**, optional. This parameter specifies the path and name of the installation package output during compilation, for example, ***xxx*/*xxx*/*xxx*.run**. Both relative and absolute paths are supported. If no path is specified, the package is generated in the current path. If no package name is specified, the package is named **static\_kernel\_*$\{datetime\}*\_$\{pid\}.run** by default.

    Compilation is successful when a message similar to the following is displayed.

    ```text
    generate run package static_kernel_${datetime}_${pid}.run success
    ```

    > **Note:**
    > - The operator compilation tool provides the **--count** parameter, which is used together with the **-p** parameter to count the number of operator information statistics JSON files in the directory specified by **-p**.
    >   The following is an example:
    >
    >   ```bash
    >   op_compiler -p <dump_dir> --count
    >   ```
    >
    >   Only dynamic shapes can dump operator statistics. After a static kernel package is installed, the statistics of the operators corresponding to the static kernel package are no longer dumped. Therefore, after the static kernel package is installed, if the network is adjusted, you can determine whether the static kernel package matches the current network by comparing the number of JSON files dumped before and after the adjustment.
    >   Perform a dump operation once before and once after the network adjustment, and use the `--count` command to count the number of JSON files generated by the dump. If the number after the adjustment is greater than that before the adjustment, some operators in the static kernel package no longer match the current network. In this case, developers can:
    >
    >   - Uninstall the static kernel package, perform the dump process again, and compile and install a new static kernel package.
    >   - Continue to use the current static kernel package. In this case, note that the unmatched operators will go through the dynamic process and will not benefit from the performance improvement.
    > - Compilation commands are not supported in **dump\_dir**.

3. Install the static kernel package.

    Go to the directory where the **static\_kernel\_*$\{datetime\}*\_$\{pid\}.run** package is located, and execute the RUN package as the running user (for example, **HwHiAiUser**):

    ```bash
    ./static_kernel_${datetime}_${pid}.run
    ```

    The following message indicates that the installation is successful.

    ```text
    Verifying archive integrity...  100%   SHA256 checksums are OK. All good.
    Uncompressing STATIC KERNEL RUN PACKAGE  100%
    ```

    Currently, installation to a specified directory is not supported. The RUN package is installed to the `{install_path}/opp/static_kernel` path by default, where **$\{install\_path\}** is the file storage path after the CANN software is installed. Replace it with the actual path.

    > **Note:** The default permission of the RUN package installation path **\$\{install\_path\}/opp/static\_kernel** is 770 (accessible to the current user and users in the same group). If the static kernel package installation fails due to insufficient permissions, contact the user who installed the CANN software package to modify the permission of the **static\_kernel** directory.

    The following is an example of the directory structure after the RUN package is installed:

    ```text
    |-- ${install_path}/opp/static_kernel
        |-- ai_core
            |-- config
               |-- ascendxxxx
                   |-- binary_info_config.json             # Total index of all static kernel packages
            |-- config.ini                                 # Configuration file that records the installation sequence.
            |-- static_kernel_250924103634186357_988879    # Static kernel file with the timestamp "250924103634186357" and process ID "988879"
               |-- ascendxxxx
               |   |-- Add                                 # Operator binary directory
               |      |-- static_kernel_Add_float16_NCL_xxxx_d0.json
               |      |-- static_kernel_Add_float16_NCL_xxxx_d1.json
               |      |-- static_kernel_Add_float16_NCL_xxxx_d0.o
               |      |-- static_kernel_Add_float16_NCL_xxxx_d1.o
               |   |-- xxxx
               |      |-- static_kernel_xxx.json
               |      |-- static_kernel_xxx.o
               |   |-- ......
               |-- config                              # Index of a single static kernel package
               |   |-- ascendxxxx
               |       |-- binary_info_config.json
               |-- scripts                             # Common scripts used by the tool
               |   |-- ......
               |-- uninstall.sh                        # Uninstall script for a single package
            |-- static_kernel_xxxx                     # Static kernel files with different timestamps
            |-- uninstall.sh                           # Uninstall script for all packages
            |-- version.info                           # Version information
    ```

    > **Note:** Multiple kernel packages can be installed. If multiple packages contain the same operator kernel, the kernel package installed later takes effect.

4. (Optional) When the static kernel package is no longer needed, you can uninstall a single package or uninstall all packages.
    - Uninstalling a single package

        Go to the installation directory of the **static\_kernel\_*$\{datetime\}*\_$\{pid\}.run** package and run **uninstall.sh** as the running user (for example, **HwHiAiUser**).

        ```bash
        cd ${install_path}/opp/static_kernel/ai_core/static_kernel_${datetime}_${pid}
        ./uninstall.sh
        ```

        If the uninstallation succeeds, the **static\_kernel\_*$\{datetime\}*\_*$\{pid\}*** folder under the **ai\_core** directory will be deleted.

    - Uninstalling all packages

        Go to the `${install_path}/opp/static_kernel/ai_core` directory and run **uninstall.sh** as the running user (for example, **HwHiAiUser**).

        ```bash
        cd ${install_path}/opp/static_kernel/ai_core/
        ./uninstall.sh
        ```

        If the uninstallation succeeds, all content under the **ai\_core** directory will be deleted, and all installed kernel packages will be uninstalled.
